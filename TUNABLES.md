# Tunables

The load-bearing constants and defaults that shape this harness's behavior,
each with where it lives, why it's set where it is, and the evidence behind
that value — a structured index into DESIGN-LOG.md's evidence, organized by
constant instead of by session, so "has this been reconsidered" is a lookup
here instead of a grep through 2,300+ lines.

**The rule for this file, same as DESIGN-LOG.md's: a value without a source
is a guess wearing a suit.** When you change one of these, update its row —
new value, new rationale, new evidence — in the same commit as the code
change, not as a follow-up. When a value has never been independently
measured, this file says so plainly rather than inventing a justification;
see `max_step_attempts` below for what that looks like.

## When to add a row here

Any new module-level constant that gates a retry count, a timeout, a budget,
or a size cap belongs here the same session it's introduced — not as cleanup
later. If you can't yet point to a measurement, write the row anyway and say
so plainly (see `max_step_attempts`); a flagged gap is far more useful to the
next person than a plausible-sounding guess, and it's the checklist for what
to measure next.
